# First signed native menu-bar trial

Outcome: prove the public spacer path inside the rewritten app. Use an owned
fixture instead of moving the user's third-party icons.
Proof: three real collapse/reveal cycles with paired readable pixels at the
same recorded screen rectangle, plus guided native arrangement and a clean
action clip. A saved choice, AX frame or successful permission read alone is
not a physical hiding result.
Constraints: the private lock bridge stays unavailable. Restore the original
app and test preferences. Keep private captures local. Use one finite Mac
trial with a saved start time, a deadline and a prepared restore action.

## Artifact and preparation

The parent supplies the exact candidate URL, archive size, SHA256, source SHA
and pinned certificate. Check all of these, strict deep signing and the plist
flags before changing an app. Candidate-only version 0.22.0 build 64 is not a
published update. Launch through Launch Services, not the raw executable.

Save the installed app identity, executable hash, complete exported preference
domain, clipboard bytes and the current input/session state. Prepare a bounded
restore guard before replacing the app. Compare settings again after the old
app quits, so its last preference flush is included. Preserve any concurrent
user changes instead of importing an old snapshot over them.

For this first focused trial, temporarily turn off flux.notch.enabled and
flux.automaticUpdateChecks before the candidate launches. Keep the original
values, including absent keys. The new app then creates no clipboard/media or
shelf feature. Do not reset grants, edit the TCC database, change a third-party
allow flag or use an assessment assertion. A normal Screen Recording prompt
from the app's explicit preview button is within this test; record any grant
change. Stop for a user-only authentication challenge.

Use a fresh mode-700 directory below the app user's actual Foundation
temporary directory. Launch the installed candidate with:

```text
environment: FLUX_ALLOW_UNVERIFIED_POSITION_BACKEND=1
arguments: --settings --capture-menu-dir <private-directory>
```

The environment flag opts this trial into the unverified public spacer path.
It is off by default. Confirm the returned process is the new candidate at
the requested path before interacting or signaling it.

## Owned fixture and actions

Use one disposable AppKit fixture, with an unambiguous label such as
FLUX-TEST, an actual bundle ID and a status item whose width can be changed.
It needs no capture access and must not read clipboard, media or calendar.
Keep its process, source and cleanup explicit. Move only this fixture and
Flux's own boundary markers. Do not rearrange Notion, TG Pro or unrelated
items in this trial. Check the fresh source identity and input state before
any drag. Input must stop if the user resumes work.

Open Settings > Menu Bar and use Arrange in Menu Bar. With the real native
Command-drag gesture, place the owned fixture between the two labeled
boundaries. Click Done after the gesture settles. Record what the UI says;
the rewrite does not post synthetic drags or claim a private policy write.

Reveal all with the actual Flux menu. Get a readable fixture baseline, then
collapse and reveal three times. Record both the action and the settled
pixels. Afterward repeat one pair with a wide fixture. Check Always Hidden
separately only if the main Hidden route passes. Keep an escape ready: opening
the Menu Bar page reveals all, and quitting this candidate removes its owned
spacers. If the arrow becomes unreachable, use that escape and report it.

## Capture in the real app

The candidate accepts SIGUSR1 only when --capture-menu-dir was supplied.
Send that signal only to the independently verified candidate PID. Each
request writes menu-NNN.png and receipt-NNN.json. There are at most twelve
requests and no capture stream. The receipt records the source revision,
process, time, global rectangle and output dimensions.

If Screen Recording is denied, use the app's explicit Show Real Icons action
and the normal system prompt/settings route. After that distinct permission
change, one fresh request is useful. Do not restart the old capture-probe
loop. A successful same-process capture is the observation path here.

Inspect every delivered frame. If a baseline remains unreadable, record the
phase receipt and stop the physical verdict. Do not label black pixels as
hidden. Compare identical global rectangles and dimensions. The raw strip
can contain private calendar text; publish only inspected crops of the owned
fixture/control, with the original crop coordinates retained in the report.

Record the actual Settings actions in a window-only clip where supported.
An alert-covered window, another Space, a settled-state recording or a still
converted to video is not a clean action recording.

## Restoration and verdict

Quit only the verified candidate and owned fixture, restore the original
signed app and the temporary preference edits, and relaunch one original
process. Check its version, hash and signer. Compare all preference values
and clipboard bytes. No third-party physical reorder should need restoration
because this trial moves only the owned fixture.

Report observed outcomes for launch, settings, preview permission, each
physical pair, guided arrangement, arrow reachability and cleanup. Mark
unrun cases explicitly. A pass accepts this source's public spacer component,
not the lock bridge, every widget, full migration, performance or release.
